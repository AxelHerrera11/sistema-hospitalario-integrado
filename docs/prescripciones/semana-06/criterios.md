# Criterios de revisión de la presentación

Estado: `PROPUESTO`; criterios cualitativos, sin ponderaciones asignadas.

| Aspecto | Evidencia requerida |
|---|---|
| Trazabilidad | Cada regla explicada se relaciona con un requisito, criterio y prueba identificable. |
| Reglas clínicas | Se distinguen los resultados de `mild`, `moderate`, `unknown`, `severe` y `life_threatening`. |
| Persistencia | Se demuestra que un 422 no guarda ni modifica datos. |
| Límites | Se identifica la responsabilidad de dominio, aplicación, puertos y adaptadores sin atribuir implementación pendiente. |
| Seguridad | Se explica autenticación, tenant y permisos con referencia al contrato aprobado. |
| Errores | Las fallas de dependencias se representan explícitamente. |
| Privacidad | La demostración usa datos sintéticos y evita información identificable. |
| Honestidad de evidencia | Cada afirmación de prueba o despliegue incluye una salida reproducible o se etiqueta pendiente. |

La evaluación no debe transformarse en una calificación numérica hasta que el
curso defina la rúbrica y sus pesos.
